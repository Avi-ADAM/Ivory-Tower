# מגדל השן · Ivory Tower

**מפת טיעונים לחקירה שמתפצלת.** קבוצה של חוקרים, או כל אחד, בונה מפה של שאלות,
עמדות, טיעונים בעד ונגד, ראיות וסינתזות. המערכת **לא מכריעה** מי צודק: כל נתיב
נשאר פתוח עד שמי שהולך בו מגיע לסופו, ומבוי סתום נשאר במפה כחלק מהידע.

אתר אחות של [1lev1](https://1lev1.com). שם מחליטים יחד ובאופן אחיד, וכאן חוקרים
בכמה נתיבים במקביל. מודל הנתונים המלא: [`docs/MODEL.md`](docs/MODEL.md).

> *An argument map for inquiry that branches. Questions hold several positions,
> positions branch (X.x, X.y), any claim gathers arguments and evidence for and
> against, and nothing is ever decided by a vote. A sister site of 1lev1.*

## מה יש ב-MVP

- **מרחבים** (`/s/<slug>`): לכל תחום מחקר מרחב משלו, עם שאלות פתוחות.
- **חמישה סוגי צמתים:** שאלה · עמדה · טיעון · ראיה · סינתזה.
- **גרף ולא עץ:** אותו טיעון יכול לשרת כמה טענות ("לקשר צומת קיים לכאן"). העץ
  (`?view=tree`) הוא תצוגה מהשורש שבחרתם, וצומת שמופיע פעמיים מסומן ↺.
- **ענפים:** עמדה יכולה להתפצל לתת-עמדות (X.x), לכל עומק.
- **הוספת שלב באמצע:** הקשר A → C הופך ל-A → B → C, והקשר הישן נשמר בהיסטוריה.
- **סינתזה בלי מחיקה:** עמדה מאחדת מצביעה על כל העמדות שהיא מאחדת, וכולן נשארות.
- **מהדורות:** רק מי שכתב צומת עורך אותו, וכל עריכה היא מהדורה חדשה. תגובה
  לגרסה ישנה מסומנת ⟳ "הטענה השתנתה מאז".
- **מצב מבני**, שנגזר מהמבנה ולא מהצבעה: לא נוסה להפריך / יש התנגדות פתוחה /
  ההתנגדויות נענו.
- **סטטוס חקירה לענף:** בחקירה · הגיע למסקנה · מבוי סתום · מוקפא, תמיד עם נימוק.
  אפשר לסמן "נבלע ב-".
- **עמדה אישית:** מסכים / לא מסכים / לא בטוח. פרטית כברירת מחדל, ואין ספירת
  קולות שמכריעה משהו.
- **ייחוס:** "מיוחס ל-קאנט" בנפרד ממי שהכניס את הטענה, כדי שאפשר יהיה למפות
  ויכוחים היסטוריים.
- **מסמכים עם סימון קטעים:** מסמך הוא רצף בלוקים, וכל בלוק הוא צומת במפה. מסמנים
  קטע בטקסט ובוחרים נגד, בעד, חלופה או שאלה. התגובה נשמרת עם עוגן על הקטע,
  מודגשת בטקסט ומופיעה בשוליים. המסמך עצמו לא משתנה. בבלוק שיש לו חלופות,
  הקורא בוחר מה לקרוא: המקור, חלופה, או שניהם זה לצד זה. אם מחבר המסמך משכתב
  את הקטע, התגובה מסומנת ⚠ "הקטע כבר לא מופיע".
- **טקסט עשיר:** Markdown בסיסי (מודגש, נטוי, קישורים, כותרות, רשימות, ציטוט),
  עם רינדור בטוח משלנו שלא מעביר HTML גולמי.
- **גשר לרקמות של 1lev1:**
  - **מרחב של רקמה:** כשפותחים מרחב אפשר לבחור את אחת הרקמות שלך כמחזיקה בו,
    ואפשר להגביל את הקריאה לחברי הרקמה בלבד. מי שלא חבר ברקמה מקבל 404, גם
    בקריאה וגם בכתיבה.
  - **מי מגיב:** במרחב של רקמה אפשר לקבוע שרק חברי הרקמה מגיבים. כך רקמה יכולה
    לפרסם את המפה שלה לכולם ולהשאיר את הכתיבה לחברים. מי שאינו חבר קורא הכל
    ויכול לסמן עמדה אישית, אבל לא רואה טפסי הוספה, ובקשת כתיבה מזויפת מקבלת 403.
  - **מענף לעבודה:** מכל צומת אפשר לפתוח **משימה פתוחה** או **תהליך** באחת
    הרקמות שלך. ברקמה עם כמה חברים זו הצעה שהרקמה מחליטה עליה לפי כללי ההסכמה
    שלה. מגדל השן לא מחליט כלום, הוא רק רושם את הקישור ומציג אותו על הצומת.
    בתיאור המשימה יש קישור חזרה לדיון.
  - **מצב העבודה:** על הצומת מוצג מה שקרה ברקמה: ממתינה להסכמה, אושרה ופתוחה,
    נלקחה, נסגרה, או הוסרה. המצב מתרענן כשחבר/ה ברקמה פותחים את הצומת, ומי
    שאינו חבר רואה את המצב האחרון שנרשם ומתי הוא נבדק. דורש את ה-qid
    `ivoryWorkStatus` ב-1lev1.
- עברית ואנגלית, RTL, מצב כהה ומובייל.

## הרצה

```bash
npm install
npm run dev          # http://localhost:5173
npm test             # vitest: המודל הטהור + המאגר מול PGlite בזיכרון
npm run check        # svelte-check
npm run build && node build
```

בלי שום הגדרה האתר רץ על **PGlite**, שהוא Postgres מוטמע, בתיקייה `./data/pglite`.
בפרודקשן מגדירים `DATABASE_URL` ל-Postgres אמיתי. אותו SQL רץ בשניהם, והסכמה
(`src/lib/server/schema.sql`) רצה בעלייה ובטוח להריץ אותה שוב.

## פריסה

- **Vercel:** ה-adapter נבחר אוטומטית, `adapter-vercel` כש-`VERCEL=1` (Vercel מגדיר
  אותו בבנייה). צריך להגדיר בפרויקט `DATABASE_URL` ל-Postgres (למשל Neon, Supabase
  או Vercel Postgres). בלעדיו האתר רץ **במצב הדגמה**: מסד זמני ב-`/tmp` שנמחק,
  עם פס אזהרה בכל עמוד.
- **Docker / שרת:** `npm run build && node build` (`adapter-node`). בלי
  `DATABASE_URL` הנתונים נשמרים ב-PGlite ב-`DATA_DIR`.
- `ADAPTER=node|vercel` כופה adapter מסוים.

## התחברות: אותה התחברות של 1lev1

האתר יושב על תת-דומיין של `1lev1.com`, ולכן הדפדפן כבר שולח אליו את העוגייה `jwt`
ש-1lev1 כותב ל-`.1lev1.com`. כשמוגדר `STRAPI_URL`:

1. `hooks.server.ts` שואל את Strapi של מי הטוקן (`/api/users/me`, עם
   `x-strapi-gate`), ושומר את התשובה ל-5 דקות.
2. בכניסה הראשונה נוצר משתמש מקומי שמקושר ל-`lev_user_id`.
3. "כניסה" שולחת ל-`https://1lev1.com/login?from=<הכתובת כאן>`, ו-1lev1 מחזיר לכאן.
4. "יציאה" מוחקת את עוגיות ה-session המשותפות, כלומר יוצאת גם מ-1lev1.
5. **הגשר לרקמות** (`src/lib/server/levBridge.ts`) קורא ל-`/api/send` ול-`/api/action`
   של 1lev1 **בשם החבר/ה ועם הטוקן שלו/ה**: רשימת הרקמות דרך `64getUserProjectList`,
   משימה דרך `createMission` ותהליך דרך `createProcess`. 1lev1 בודק חברות ברקמה
   כמו בכל דף שלו, ולכן אין למגדל השן שום סוד שמאפשר לו יותר ממה שהחבר/ה
   יכולים לעשות בעצמם, ולא נדרש שינוי ב-1lev1, חוץ מה-qid `ivoryWorkStatus` (קריאה בלבד, לחברי הרקמה) שמוצג בו מצב העבודה.

בלי `STRAPI_URL` (פיתוח מקומי) נכנסים עם שם תצוגה בלבד.

| משתנה | |
|---|---|
| `DATABASE_URL` | Postgres. בלעדיו: PGlite ב-`DATA_DIR` |
| `DATA_DIR` | ברירת מחדל `./data/pglite` |
| `STRAPI_URL` | מפעיל התחברות דרך 1lev1 |
| `STRAPI_GATE_KEY` | הסוד של nginx מול Strapi (אותו ערך כמו ב-1lev1) |
| `LEV_LOGIN_URL` | ברירת מחדל `https://1lev1.com/login` |
| `LEV_URL` | 1lev1 עצמו, בשביל הגשר לרקמות. ברירת מחדל `https://1lev1.com` |
| `WORK_STATUS_REFRESH_SECONDS` | כל כמה זמן ביקור של חבר/ה ברקמה בודק שוב את מצב המשימה. ברירת מחדל 120 |
| `ORIGIN` | הכתובת הציבורית (adapter-node), למשל `https://tower.1lev1.com` |

> 1lev1 כבר מקבל `from` לכל `*.1lev1.com` (`isOwnHost` ב-`src/lib/auth/redirectTarget.js`),
> כך שלא צריך לשנות שם כלום.

## מבנה הקוד

```
src/lib/model/      טהור ונבדק: סוגים, כללי קישור, מצב מבני, בניית עץ, צורת מסמך
src/lib/anchor/     עוגני ציטוט (quote.ts) והדגשה ב-DOM (dom.ts)
src/lib/text/       Markdown בטוח
src/lib/server/     db (PGlite/pg), schema.sql, repo (כל הכתיבה והקריאה), levAuth
src/lib/i18n/       he.json, en.json; t('ns.key', { count }) עם {{count}}
src/routes/         /, /login, /lang, /s/[space], /s/[space]/n/[id], …/edit
```

כל הקשתות הולכות **מהמגיב אל מה שהוא מגיב לו**: טיעון `opposes` את העמדה שהוא
תוקף, ועמדה `answers` את השאלה שלה. כללי הקישור המותרים מוגדרים במקום אחד בלבד,
`src/lib/model/rules.ts`.
